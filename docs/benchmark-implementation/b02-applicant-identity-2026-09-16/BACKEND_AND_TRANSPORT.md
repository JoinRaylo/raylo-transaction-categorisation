# Backend and transport evidence

Backend source was inspected at immutable [`api@1958895`](https://github.com/JoinRaylo/api/tree/1958895ae9785c40a5217021eadf15ccb0efcbde), not attested as the deployed version. The monorepo source is immutable [`internal-services-monorepo@de6efc790c79c6ff9726993c504b355bfcd2ca2e`](https://github.com/JoinRaylo/internal-services-monorepo/tree/de6efc790c79c6ff9726993c504b355bfcd2ca2e).

An anonymous checkout has its own UUID, encrypted/signed token, and display reference. `checkout_customer_infos` is one-to-one with checkout and has no person foreign key. Checkout creation can attach an already-resolved Auth0 User, but request context only resolves an existing user; it does not create one. During order conversion, `CreateOrderCommand` resolves or creates the local User before lock/accept, then links checkout/customer and creates or finds the Order. See [`checkout.rb`](https://github.com/JoinRaylo/api/blob/1958895ae9785c40a5217021eadf15ccb0efcbde/app/models/checkout.rb#L24-L72), [`checkout_customer_info.rb`](https://github.com/JoinRaylo/api/blob/1958895ae9785c40a5217021eadf15ccb0efcbde/app/models/checkout_customer_info.rb#L29-L45), [`extract_context_from_request_command.rb`](https://github.com/JoinRaylo/api/blob/1958895ae9785c40a5217021eadf15ccb0efcbde/app/commands/public_graph_ql/extract_context_from_request_command.rb#L40-L67), and [`create_order_command.rb`](https://github.com/JoinRaylo/api/blob/1958895ae9785c40a5217021eadf15ccb0efcbde/app/commands/create_order_command.rb#L26-L63).

Plaid Link starts with the risk-result `user_id`; Asset Report construction separately sets `client_report_id = checkout.id` and `client_user_id = checkout.user&.id`, blank for anonymous checkouts. Plaid `item_id` belongs to the checkout-owned banking connection. No `persistent_account_id` or cross-checkout account reuse lookup is present in the inspected integration code. Sumsub uses checkout UUID as `externalUserId`, so its applicant ID is checkout/proof scoped. See [`construct_starting_data_command.rb`](https://github.com/JoinRaylo/api/blob/1958895ae9785c40a5217021eadf15ccb0efcbde/app/mediators/banking_connections/plaid/construct_starting_data_command.rb#L12-L22), [`construct_risk_assessment_data_command.rb`](https://github.com/JoinRaylo/api/blob/1958895ae9785c40a5217021eadf15ccb0efcbde/app/mediators/banking_connections/plaid/construct_risk_assessment_data_command.rb#L56-L72), [`construct_risk_assessment_data_command.rb`](https://github.com/JoinRaylo/api/blob/1958895ae9785c40a5217021eadf15ccb0efcbde/app/mediators/banking_connections/plaid/construct_risk_assessment_data_command.rb#L117-L128), and [`create_or_find_applicant_command.rb`](https://github.com/JoinRaylo/api/blob/1958895ae9785c40a5217021eadf15ccb0efcbde/app/mediators/proofs/sumsub/commands/create_or_find_applicant_command.rb#L16-L66).

The extractor requires Airbyte request `id` as `external_request_id`, retains it on fan-out rows, and parses report-root `asset_report_id` and `client_report_id`. It also retains Plaid account and transaction IDs. These are provider-scoped observation/grouping keys: recurrence across reports is expected and can detect repeat events; alias/reconnection completeness and person ownership remain unverified. See [`parsers.py`](https://github.com/JoinRaylo/internal-services-monorepo/blob/de6efc790c79c6ff9726993c504b355bfcd2ca2e/apps/payload-extractor/src/payload_extractor/parsers.py#L296-L312) and [`parsers.py`](https://github.com/JoinRaylo/internal-services-monorepo/blob/de6efc790c79c6ff9726993c504b355bfcd2ca2e/apps/payload-extractor/src/payload_extractor/parsers.py#L532-L635).

The categoriser API and staging app implement the frozen contract: they accept explicit `assessment_id` and `assessment_ts`, plus the nested Plaid report; sensitive customer/owner fields are excluded. Only the Rails/Taktile caller-context integration remains proposed/pending. `assessment_id` anchors the ledger key, while transport-only request fields are excluded from the semantic input hash. See [`types.py`](https://github.com/JoinRaylo/internal-services-monorepo/blob/de6efc790c79c6ff9726993c504b355bfcd2ca2e/lib/raylo-txncat/src/raylo_txncat/types.py#L143-L168), [`discovery.py`](https://github.com/JoinRaylo/internal-services-monorepo/blob/de6efc790c79c6ff9726993c504b355bfcd2ca2e/apps/ob-txn-categoriser/src/ob_txn_categoriser/discovery.py#L254-L344), and [`hashing.py`](https://github.com/JoinRaylo/internal-services-monorepo/blob/de6efc790c79c6ff9726993c504b355bfcd2ca2e/lib/raylo-txncat/src/raylo_txncat/hashing.py#L81-L97). This gives assessment/replay correlation, not applicant identity.

Candidate email/canonical-email links are operational matching signals used at customer conversion and similarity checks; see [`find_or_create_customer_command.rb`](https://github.com/JoinRaylo/api/blob/1958895ae9785c40a5217021eadf15ccb0efcbde/app/commands/find_or_create_customer_command.rb#L21-L80). They are candidate links, not automatically authoritative across anonymous applications. Treat cross-checkout identity as established only by an authoritative User/Customer binding or separately reviewed link evidence. A new UUID only creates another correlation key and does not solve reuse or ownership.
